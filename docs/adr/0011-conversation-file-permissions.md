# ADR-0011：会话文件区与逐次文件审批

> 后续更正：仅限会话文件区及首次新建自动批准的策略已由 [ADR-0012](0012-approved-local-file-access.md) 替代。当前支持用户授权的真实本地目录，所有写入和删除均需人工审批。本文件保留初始切片的设计记录。

- 状态：Accepted
- 日期：2026-09-05
- 来源：产品负责人要求为 Harness 增加文件读、写、删除，并对危险操作施加用户审批。

## 决定与边界

通过 Enterprise 的 `ConversationFileService` Host Adapter 注册 `file_list`、`file_read`、`file_write`、`file_delete`。不引入 Shell、文件系统库或新 Loop。工具只操作当前租户、工作区、会话中的文本文件区，不接受任意电脑路径，也不能修改原始上传附件、Fact 或已批准需求单。

首次新建路径可由固定策略批准。覆盖、在已删除路径上恢复、删除均需用户在界面逐次批准；`expectedVersion` 必填，`null` 仅表示从未存在的路径。审批绑定操作、内容摘要、路径、当前版本、请求幂等键、发起人和会话身份；不提供“总是允许”。用户只能批准或拒绝已保存的请求，不能通过审批接口替换内容。

文件名仅作为逻辑路径；物理目录使用作用域 SHA-256，版本对象使用固定的 Artifact ID 与版本号。阻止绝对路径、`..`、隐藏路径、反斜线、符号链接和硬链接对象。范围是 UTF-8 txt/md/csv/json/html/svg，每个文件最多 128 KiB；版本内容总量和索引各限 20 MiB，每会话最多 512 次写入审批记录。HTML/SVG 只以纯文本预览和下载，不在页面执行。

重要输出形成 `task-files.v1` 结构化索引及不可变文本 Artifact Version，包含路径、内容哈希、版本、生成时间、发起人、Execution ID 和 Approval ID；完整审批记录还绑定 Tool Call、幂等键、决策人、决策时间及操作结果。执行使用 Core 的审计、执行账本和工具 Receipt。文件属于任务草稿，不构成已验证包装生产参数或已批准生产交付。

## Core 兼容扩展

`AgentToolApprovalPort.authorize` 增加可选 `AbortSignal`。Loop 用已有 `abortable` 等待审批，并在执行前重新检查取消，防止不响应取消的审批 Adapter 稍后返回批准导致写入。已有立即返回的 Approval Adapter 保持兼容。

`createIdempotencyKey` 增加可选作用域参数（tenant/workspace/run）。文件工具将其纳入幂等键，避免两个会话使用同一个消息 ID 时共享执行结果；已有 Background/Cron Tool 的键算法保持不变，避免升级后重放旧副作用。

## 持久化、取消与恢复

审批请求先持久化，刷新页面或重建 Service 后仍能查看和决策。审批沿用当前 Turn 的两分钟总预算，停止/超时使等待中请求失效；不存在永久后台授权。重启后可在未过期时决策并继续原回复；过期、拒绝或已取消的请求不会重新执行，需明确发送新指令。

写入顺序为：校验审批和当前版本、校验原内容哈希 → 创建并 fsync 不可变文本版本 → 原子替换并 fsync 索引。索引一次提交版本、审批状态与结果；崩溃留下的未引用版本仅在内容完全一致时可复用，否则报恢复冲突。删除只追加 tombstone 版本，不永久销毁内容；用户可以查看和下载旧版本，或要求 Agent 按最新 tombstone 版本重新申请恢复。

Core 账本若处于 `started/unknown`，继续使用既有保守规则：不自动重复副作用。文件索引中的已提交结果可供人工核对；本切片不承诺自动修复跨账本崩溃窗口。会话删除后所有文件、审批及历史读取入口均拒绝访问，保留数据用于审计。

## 替代方案、限制与退出条件

- 任意项目目录写入或通用 Shell：不采用，会扩大权限边界并可能覆盖已批准交付或 Secret。
- 原地覆盖、永久删除：不采用，无法保持版本和恢复证据。
- 只显示确认弹窗：不采用，审批必须在 Host 执行路径内校验。
- 为此新增通用业务状态框架：不采用，复用现有 Core 策略、审计和执行账本，文件服务管理自己的 Artifact 索引。

当前使用单个本地 Host 的同步文件操作串行提交，等待审批不持有锁；不要让多个 Host/独立进程共享该文件存储目录。文件区不提供多人角色管理、二进制编辑、永久清理或自动恢复未知账本。需要多进程/多机写入时迁移到事务存储和对象存储 Adapter，并补充并发和崩溃故障注入验证。

无需迁移现有资料；配置 `BLACKX_FILE_STORE_PATH` 后重启 Host 即可启用。未来扩大目录、文件类型或发布权限必须形成独立授权和回归证据。验证见 [文件操作验收](../evidence/conversation-files-2026-09-05.md)。
