# ADR-0013：由 Agent 发起即时文件审批

- 状态：Accepted；2026-09-05。
- 来源：用户明确要求 Agent 询问是否允许保存到具体位置，拒绝手动预授权目录的交互。
- 替代 ADR-0012 的目录授权机制，沿用现有 Core 审批端口；属于 Enterprise Host Adapter 与 UI 调整。

## 决定

用户直接提出文件任务。Agent 通过只读 `file_list` 获得真实本机位置，优先采用用户指定的位置；准备好绝对路径、完整内容和预期文件哈希后调用写入或删除工具。Host 持久化审批卡片并暂停工具，显示具体操作、路径及修改前后内容。用户批准一次后继续执行，拒绝、停止或超时不执行。聊天中的“同意”与模型输出不构成审批决定。

取消目录授权表单及授权/撤销客户端方法。旧 POST/DELETE 目录授权 API 返回 410；GET 目录浏览与文件读取仍按 Host 策略执行，不需逐次审批。历史目录授权记录不再提供权限。旧本地审批缺少当前父目录身份，不能执行；读取列表时取消这类尚未执行的旧请求，保留历史备份与审计。

每次审批绑定用户、tenant/workspace/conversation、操作、绝对路径、完整内容摘要、文件当前 SHA-256 与身份、父目录设备/inode、幂等键。执行前重新校验，内容或目录变化必须重新审批。同一审批不能改写其他路径/内容，也不能跨会话使用。重复成功调用返回原收据，不重复修改磁盘。

## 边界

这是单用户本机 Host 文件能力。HTTP Token、Host/Origin 校验、Host 注入身份继续生效；文件适配入口额外拒绝非当前 Host 的 tenant/workspace/actor。没有向多租户远程服务开放任意磁盘读取。保护系统目录、隐藏路径、凭据类型、Blackx 内部状态及交付目录，拒绝符号链接、硬链接、设备和路径跳转。普通读取无用户审批；写入（包括新建）和删除始终需要单次人工批准。

仅支持现有目录中的 UTF-8 文本（128 KiB），不提供目录创建/递归删除或通用 Shell。父路径必须为规范绝对路径，不经过符号链接。Agent 应使用工具返回的真实位置；二进制文件继续走专用工具。

修改与删除前保存不可变原文备份和执行意图；原路径修改与索引完成之间崩溃时保持未知副作用语义，禁止盲目重试。新建使用原子 no-clobber 写入。父目录/文件身份与哈希校验能检测审批期间变化，但不是针对同 UID 恶意进程的跨进程原子比较交换，仍保留 ADR-0012 的本机并发限制。

## 验收与退出

固定单测和真实 HTTP 离线产品测试必须证明：无目录授权也能读取和提出写入；批准前原文件不变；拒绝/停止/过期阻断执行；路径内容及跨会话审批复用失败；父目录替换失效；批准后磁盘改变且原文可追溯。UI 应无需任何目录设置，展示 Agent 发起的审批。

若扩展到多用户远程 Host，必须先提供各用户的文件系统隔离与访问策略，不沿用单机所有者身份映射。后端代码更新需重启 Host，前端刷新后移除旧授权入口。
