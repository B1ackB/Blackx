# ADR-0016：Plan 到需求单的交接与本地维护边界

状态：Accepted

日期：2026-09-13

## 背景与决定

用户授权本次会话补全本地产品，并说明真实员工、素材和企业环境暂不可用。采用 [工作单](../local-product-completion.md) 的范围，以合成包装资料和离线 Provider 验证工程行为。

Plan 编排继续属于 Enterprise Layer；包装来源交接、字段与导出落在 Manufacturing 层。已有 Workspace Controller 增加可选的启动资料准备回调，使没有聊天消息的结构化来源也能启动工作流。Core 不增加业务入口或模型路由。

## 交接契约

- 用户选择已完成的最新计划版本，由 Host 读取所属会话的持久快照；请求正文不能提供或伪造子任务结果。
- 校验计划确认、完成、会话版本和附件索引，再产生 `plan-requirement-source.v1` 资料快照。超过既有 32,000 字符限制时拒绝。
- 快照写入既有 `customer_brief` 输入，新增受保护的 `plan_source` 事实引用。内容保持 model_output / unverified，不等于业务事实确认。沿用命令幂等、事件、Artifact 输入事实版本与交付审批。
- 来源仍使用 Conversation 关联来解析既有附件。模型根据报告提取候选字段时不获得权威身份，冲突必须保留供核对；工程 fixture 不证明真实模型能正确识别冲突。
- 导出按 Artifact 的输入事实版本恢复来源计划引用，不引用任意最新计划。历史快照不可变；主动导入新版本才更新此工作流来源并使旧 Artifact 失效。

## 包装字段兼容

在 `requirement-brief.v1` 中扩展六种可选标准字段，既有七个基础字段不变。旧文档无需迁移。任何已填字段（包括补充字段）未确认时都不能审批。旧版本程序不认识新字段，因此降级须使用升级前备份；不承诺新 Artifact 可由任意旧版本消费。

这些字段仅为需求整理，不包含行业认证、材料选择或确定性生产适用判断。演示咖啡袋不是已验证的企业品类规格。

## 本地维护

`BLACKX_DATA_ROOT` 统一默认路径，保留原单项路径配置优先级。Host 与离线备份共享根目录互斥锁；不把 File/SQLite 改造成新的分布式数据库。默认不自动删除疑似过期锁，强制退出后的处理须核对进程状态。

备份保存文件集合、字节数、哈希和 SQLite WAL，验证在临时副本中进行。自动工具仅支持标准数据布局；恢复只写新目录并保留失败标记，避免覆盖用户原数据。私有配置、外部原文件和未来任意 Schema 迁移不在快照保证内。

## 替代方案、验证和退出

不新增任意 subagent Tool、汇总模型、知识库或企业连接器；复用现有 Requirement Worker 提取候选，并通过其审批流程完成交接。实时热备份需要跨 Store 一致性协议，当前采用停机备份。

测试覆盖导入来源/版本、基础字段与补充字段确认、三种导出、重复命令、File/SQLite/WAL 恢复及拒绝路径。真实模型、员工和企业环境保持待补。若后续需要更大资料包、在线备份或跨平台发行，应以实际样本补充独立设计和验收，而不扩大本次保证。
