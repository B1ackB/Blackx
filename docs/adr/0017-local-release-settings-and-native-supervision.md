# ADR-0017：本地发行、私密配置与原生资源监督

日期：2026-09-13；状态：接受。

## 背景与决定

在没有真实包装员工、企业素材和部署环境时，继续完成可离线验证的本机工程。能力落在 Host Adapter/UI；不新增 Agent Loop、业务状态机或模型厂商依赖。

- 模型设置由本机授权 API 写入独立的 `.packx-settings.json`，权限 0600、原子替换、版本冲突拒绝。仅展示模式、地址、模型及凭据是否存在，文件记录修改人和时间，不把凭据写入日志或业务备份。开发服务器同时拒绝原始私密配置、业务存储与输入副本的静态访问（包括 /@fs 路径）。空 Key 保留配置；显式清除同时屏蔽 `.env` 的 Key。保存配置只影响下次启动，当前任务不热切换 Provider。
- 任务名称采用 Host SQLite 元数据事件，保留修改人、时间与名称版本。名称修改不改变 Session/Plan 的执行版本或审批。没有自定义名称时使用最新 Plan 目标；侧栏检索名称、摘要和完整 Plan 目标。普通聊天全文检索不在本次范围。
- 发行目录使用现有 Node/tsx 和锁定依赖，预构建网页与 macOS 原生程序，使用 `Packx.command` 启动。生产模式仅服务 `dist` 的首页和资源，不运行 Vite 开发中间件。按清单打包，不包含业务数据或私密配置；不复制 Node、Apple SDK、系统框架。没有引入新的第三方依赖或打包器。
- 原生 C Supervisor 作为 Port Adapter 实现，启动独立的解析进程组，监督 Host 存活并清理子进程。Manifest 允许收紧 CPU/RSS/进程数量限制；不允许超出 Host 默认预算。以固定、经过登记的解析器和系统 unzip 为生产范围，不把该机制宣传为允许任意恶意程序的通用隔离产品。

## 资源与故障边界

默认每个解析进程 CPU 30 秒（程序可收紧），每文件大小不超过 manifest 的输出字节上限，128 个文件描述符，禁止 core dump；这些由内核 rlimit 执行。进程组总 RSS 默认 512 MiB、最多 8 个进程、输出目录字节/条目/深度通过每 20 ms 采样检查，超限结束执行并记录 `resource_exhausted`。采样存在短时超调，不等同于内核强制的组内内存配额。现有工具自身的 15 秒墙钟超时和 stdout/stderr 上限继续生效。

监督进程检测 Host 父进程消失后杀死解析进程组并清理输出目录；成功退出后由 Host 校验产物并清理。输入目录记录 Host PID，重启清理明确已退出的所有者，保留存活或无法确认的所有者。PID 被系统复用时保守保留。尚未证明进程自行脱离组、监督程序自身被强杀、系统断电与磁盘故障的全部组合；这些不属于已验证的固定解析器故障范围。

本地数据锁只能通过 `state -- recover-lock` 回收明确已消失的进程，恢复保留记录；拒绝存活或状态不明的 PID。数据布局增加版本 1 标记，旧布局只增添标记，不改写业务记录；未知版本在打开存储前拒绝。

## 替代方案与影响

不增加 Electron、自动更新框架、系统级守护服务、Keychain SDK、通用搜索服务或新依赖。私密文件不等同于系统钥匙串，不抵御本机账号被接管。首次发行启动仍需预装 Node 并联网安装锁定依赖，不能宣称完全离线的一键安装。签名、公证与干净企业设备验证待具备相应发行环境后执行。

## 迁移与退出条件

设置文件优先于 `.env` 的 Provider 项；移除设置需在停机后妥善处理私密文件。名称数据库和数据版本标记纳入整组备份。升级使用新目录和恢复副本；回退用旧代码及升级前备份，不让旧代码打开未知新版数据。若需要无 Node 前置的安装、跨平台或任意代码隔离，另立 ADR 和离线对抗基线后替换对应 Adapter。

## 验证

配置掩码/持久化/清除/冲突与链接拒绝、任务跨租户和版本隔离、原生 CPU/RSS/进程数与 Host SIGKILL、锁/输入目录恢复、旧/未知数据版本、生产 HTTP 流程、发行目录重定位启动均纳入本轮检查。实际结果见[工程证据](../evidence/local-product-completion-2026-09-13.md)。
