# 会话文件与审批验收（2026-09-05）

> 这是初始会话文件区切片的历史验收。后续已按用户要求支持真实本地目录，并改为所有写入均需审批；当前验收见 [真实本地文件](local-file-access-2026-09-05.md)。

## 交付范围

普通会话通过真实 Agent Loop 调用 `file_list`、`file_read`、`file_write`、`file_delete`。文件位于按 tenant/workspace/conversation 隔离的独立文件区，新建按固定策略授权，覆盖和删除逐次人工审批。审批卡片提供修改前后内容、批准/拒绝；文件浏览器提供历史版本纯文本预览和下载。

文件版本状态是 `draft/deleted`；删除追加新版本，旧文本对象保持不变。审批状态是 `pending/approved/rejected/cancelled/applied`，操作成功时在同一索引提交版本和结果。文件不会转变为权威 Fact 或已批准生产交付。

## 自动验收

- `npm run check`：43 个测试文件、199 项测试通过；TypeScript 和 Vite 构建通过。15 项依赖显式 macOS 原生开关的专项测试在默认测试中跳过。
- `npm run eval:offline`、`npm run eval:m1`、`npm run eval:m2`：全部通过；M2 仍为 10 个包装案例。
- `npm run eval:product`：使用临时数据、隔离端口和固定本地 Anthropic 响应，贯通真实 HTTP Provider Adapter → Core Loop → 文件工具 → 审批 API → 不可变文件版本，并同时保留真实原生 PDF 工作流、业务审批、导出、任务取消和会话删除回归。无外部模型请求。

文件专项回归覆盖：

- 文件真实落盘、同一操作重放不产生新版本、属性排序不改变幂等键、不同会话相同消息 ID 不冲突。
- 缺少批准拒绝执行、审批内容不能被替换、两个已批准操作竞争同一版本时仅首个成功。
- 拒绝删除保持内容、批准删除保留历史、恢复已删除路径需新的审批。
- 停止审批等待、过期、Service 重建后读取审批、删除会话后所有文件入口拒绝访问。
- 越界路径、隐藏路径、二进制 NUL、超限内容、符号链接、内容哈希不一致均拒绝。
- 崩溃留下的未引用版本：内容相同可复用，不同则明确报恢复冲突，原版本保持不变。
- 不响应取消的 Approval Adapter 在停止后才返回批准，也不会触发工具执行。

## 浏览器验收

使用 `npm run dev:fixture` 的隔离页面：桌面查看覆盖前后内容并批准、查看 v1；390 × 844 手机宽度下拒绝删除后再发起并批准，v3 显示“已删除”，仍能查看 v1 原始文本。无横向或整页额外溢出；新审批自动滚入可见区域。修正了展开文件区时隐藏上传 input 撑高整页的问题。

## 验证边界

本记录证明本地工程链路，不代表真实模型稳定选择工具或企业多用户生产验证。存储仅支持单个本地 Host 写入；Core `started/unknown` 账本仍需人工核对，未承诺自动消除跨账本崩溃窗口。未开放电脑任意目录、二进制编辑、永久物理删除、多人 RBAC 或改写已批准交付。完整边界见 [ADR-0011](../adr/0011-conversation-file-permissions.md)。
