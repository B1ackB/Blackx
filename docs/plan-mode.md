# Plan 模式与子 Agent

Packx 支持在聊天输入框上方切换“直接执行”和“Plan · 确认后执行”。已有会话默认直接执行。

## 使用步骤

1. 选择 Plan 模式，在输入框描述要完成的包装任务。规划参考当前会话最近 8 条可见消息（每条最多 2,000 字符）及最近 8 份附件的来源索引，不自动传入全部历史。
2. Agent 只使用文件/文档读取工具，生成最多 4 项子任务。界面展示计划版本、每项目标和所需工具。
3. 核对计划。需要修改时，在输入框提交修订要求，生成新版本。旧版本不能继续批准。
4. 点击“确认 vN 并启动子 Agent”。聊天中的“同意”不会自动触发执行。
5. Host 顺序启动独立子 Agent，界面逐项展示状态和结构化结果。文件写入/删除仍需在现有文件审批卡片中逐次确认。
6. 可以暂停、取消，或恢复已确认且可恢复的计划。运行时先暂停，再切换模式。刷新页面或重启 Host 后读取持久状态继续处理；关闭网页不会取消任务。
7. 计划完成后点击“将结果转为需求单草稿”。Host 冻结该计划的目标、原上下文、确认版本、子任务结果和执行来源；在右侧逐项核对字段，生成新版本，再单独审批和导出。没有普通聊天消息的 Plan 会话也可导入。

结果中的证据和限制来自子 Agent 报告，仍需核对。计划确认不验证业务事实，不批准最终生产交付物，也不自动授权文件变更。

## 执行范围

- 子 Agent 有独立 Session、目标和工具白名单，共享父会话的本机用户权限范围。上下文独立不等于独立文件系统或独立操作系统容器。
- 每个子 Agent 可以执行被计划列出且 Host 允许的文件读取、文档读取、文本写入/删除；没有递归派生、后台任务或定时任务工具。
- 首版顺序执行独立任务，不支持任务依赖图或并行写入。需要消费前一步输出的步骤，应作为一个子任务内部的工作处理。
- 每计划最多 16 个 Runtime 执行片；每片最多 4 次模型 Loop 迭代、8 次工具调用、12,000 输入 Token，超时 60 秒。重试不重置计划预算。此限制不是精确费用估算。
- 子任务结果汇总在计划面板中，按任务顺序保留摘要、证据与限制，不自动提升为已验证需求单。
- 显式导入只接受已完成的最新计划，且会话版本与附件索引未变。来源快照最多 32,000 字符，超限拒绝而非静默丢弃；导出保留来源计划版本。重新规划不会覆盖已导入的历史快照，主动导入新版本后沿用需求单的版本失效与重新确认规则。
- 需求单允许补充材料结构、材料厚度、印刷方式、表面工艺、封口方式和排气阀要求。这些属于待核对的需求信息，不代表已验证生产规格；填写后的补充字段也必须确认才能审批。

## 失败与恢复

来源或会话变化、过期版本、无效模型输出、工具拒绝/失败、预算耗尽都会停止推进。可重试 Provider 错误可以恢复；其余错误请核对已完成结果并重新规划。

已完成子任务不会重复执行。若进程在 Session 已保存、完成 Trace 未保存的极小窗口中退出，会报告 `plan_completion_evidence_missing`，需要人工核查，不会冒险重复文件操作。暂停规划阶段会取消该次规划，可以重新生成。

## API 与存储

- `GET /api/conversations/:id/plan`：读取模式、修订号、计划版本和子任务结果。
- `POST /api/conversations/:id/plan`：提交 `mode`、`generate`、`confirm`、`pause`、`resume` 或 `cancel` 命令。
- 每个命令带唯一 `requestId` 和当前 `revision`；操作既有计划时还需 `version`。确认还需 `confirmed: true`。
- 所有请求使用原有本地会话认证；身份由 Host 决定，不由模型或请求正文指定。
- 计划事件保存在 Agent 状态目录的 `plans.sqlite`；租约与执行片复用既有 Stage Job Queue。数据库应与会话、Trace、队列一同备份。

## 验证

`npm run eval:plan` 是离线单 Agent 对照评测；`npm run eval:product` 包含真实本地 HTTP 编排验收，使用固定 Provider，不需要外部模型密钥。

`npm run dev:fixture` 也提供固定计划和两个子 Agent 的演示回复。它验证 UI 与编排链路，不代表真实模型读取或分析了资料。
