# 开始使用 Packx

这个发行目录面向 macOS 本机用户，包含已经构建的网页与原生文档解析器。它尚未签名或公证，不是已通过企业电脑部署验证的安装包。

1. 安装 Node.js **24.14 或更高的 24.x 版本**，保持目录位于当前用户可写的本机磁盘。
2. 双击 `Packx.command`，或在本目录执行 `node scripts/launch.mjs`。首次启动自动按锁定清单安装依赖，需要联网；后续启动无需重新安装。发行目录已包含原生程序，不需要 Apple 编译工具。
3. 浏览器打开后点击“配置模型”，填写兼容 Anthropic Messages 的服务地址、模型 ID 和自己的 API Key，保存后停止并重新打开 Packx。保存配置不会发送模型请求；正式发起任务才会调用服务。
4. 停止时在启动窗口按 Control-C，等进程退出后再关闭窗口。正在运行的任务可能需要恢复；不可把关闭浏览器当作停止服务。

如果系统阻止打开未签名程序，请按所在组织的可信软件要求处理；不要关闭系统安全防护。当前发行物需要匹配的 macOS CPU 架构，签名、公证和干净设备测试仍待发行环境验证。

首次使用可先阅读 `examples/coffee-pouch-intake.md`。模型产出是待确认草稿，逐项核对后才能审批与导出。

本机私密连接配置在 `.packx-settings.json`，业务数据默认在 `.blackx-data`。API Key 不会被放进业务备份。运行 `npm run doctor` 检查配置，`npm run state -- backup /绝对路径/新备份目录` 创建停机备份。完整步骤见 `docs/local-operations.md`。

升级请保留旧目录，停机备份，解压新版本到**新目录**，把备份恢复到新数据目录，使用 `.env` 设置 `BLACKX_DATA_ROOT` 指向恢复位置，然后重新配置模型。先确认新版本可读、可继续任务，再处理旧目录。未来不支持的数据版本会在启动时拒绝打开；没有自动降级或覆盖业务数据。

异常退出后，执行 `npm run state -- recover-lock`，只在原 Host 进程已经消失时回收锁，并保留恢复记录。再重新启动 Packx。

`packx-release.json` 记录文件摘要，旁边的 `.tar.gz.sha256` 可核对传输完整性；摘要不等同于签名或可信发布者证明。
